# Rebrand: Rezzy Customer → "Eloquent Bookings"

**Date:** 2026-06-20
**Scope:** The customer-facing app only (`eloquent-bookings`). The provider app
(`admin`) keeps its current "Rezzy" identity. Backend customer-facing strings
are included; the shared backend itself is not renamed.

## Goal

Rebrand the public booking app from "Rezzy" to **Eloquent Bookings**, including
its internal identifiers, and migrate it onto `bookings.eloquentservice.com`
while keeping the existing `admin.eloquentservice.com` live in parallel.

## Naming decisions (locked)

| Thing | Value |
|---|---|
| Display name | `Eloquent Bookings` |
| Internal folder + package name | `eloquent-bookings` |
| PWA `short_name` | `Bookings` |
| Favicon / app-icon monogram | `EB` on the existing mint tile |
| New domain | `bookings.eloquentservice.com` |
| Old domain | `admin.eloquentservice.com` — kept live in parallel (same app) |

## Work breakdown

### A. Customer app — display strings → "Eloquent Bookings"

- `index.html` — `<title>Rezzy</title>` → `Eloquent Bookings`
- `public/manifest.webmanifest` — `name` → `Eloquent Bookings`, `short_name` → `Bookings`
- `public/favicon.svg` — replace the `R` monogram paths with an `EB` glyph;
  update `aria-label="Rezzy"` → `Eloquent Bookings`
- Regenerate PNG icons via the existing `npm run icons` script (sharp) so
  apple-touch / maskable icons match the new favicon
- `src/pages/Home.tsx` — `<AppBar title="Rezzy" …>` → `Eloquent Bookings`
- `src/components/WhatsAppButton.tsx` — `SUPPORT_MESSAGE` "Hi Rezzy team, I need
  some help." → "Hi Eloquent Bookings team, I need some help."
- `src/styles/tokens.css` — header comment mentioning "Rezzy customer"

### B. Customer app — internal identifiers

### C. Backend — customer-facing strings (shared backend, not renamed)

  "Generated by Rezzy" → "Generated by Eloquent Bookings"

Tests referencing these exact strings (e.g. `WaPromptsTest`) get updated in lockstep.

### D. Domain migration (droplet `root@64.227.153.90`)

Parallel-serve model — one app, one webroot, two domains:

1. New webroot `/var/www/eloquent-bookings` (owned `www-data`). First deploy
   uploads `dist/` here. The old `/var/www/eloquent-bookings` can be removed once
   the new path serves both domains.
2. nginx: edit the customer site (`sites-enabled/frontend`) so its `server_name`
   lists **both** `bookings.eloquentservice.com admin.eloquentservice.com`, and
   `root` points at `/var/www/eloquent-bookings`. (Or a fresh site block copied
   from the existing one — same effect.)
3. `certbot --nginx -d bookings.eloquentservice.com -d admin.eloquentservice.com
   --non-interactive --agree-tos -m francisgill1000@gmail.com --redirect`
   so the cert covers both names and HTTP→HTTPS redirect is in place.
4. `nginx -t && systemctl reload nginx`.
5. Verify: `curl -sI` 200 on both domains; a deep SPA route returns 200; HTTP→301.

`*.eloquentservice.com` is a wildcard A-record already, so no DNS step is needed.

## Out of scope

- Historical `docs/superpowers/specs|plans/*` files (point-in-time records — left as-is)

## Risks & notes

- **Folder rename churn:** `eloquent-bookings/` is referenced only in its own files,
  two backend *comments*, one `admin` CSS comment, and historical docs — no
  runtime/data dependency (the live-chat `channel` value is not the folder name).
  Comments may be updated opportunistically but are non-blocking.
- **Dev server / node_modules:** `node_modules` moves with the `git mv`; no
  reinstall needed. Restart any running `npm run dev` after the move.
- **Branch state:** work continues on `feat/eloquent-bookings-web`; tree is normally
  dirty — do not checkout master or stash.
- **Parallel domain:** keeping `admin.*` live means existing printed QR codes and
  shared links keep working; both names resolve to the same renamed app.
